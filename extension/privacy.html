SuperX 隐私政策

最后更新：2026 年 10 月 24 日 · SuperX 1.0.0

本政策说明 SuperX 1.0.0 通过 Grok 订阅 OAuth、自己的 API Key 或官方本机 Grok Build 提供事实核查、可选评论建议和未发布草稿核查（包括图片输入）时的数据处理。草稿文字与受支持的附图仅在你明确请求核查草稿时发送。SuperX 是独立项目，与 X、Grok 或 xAI 没有官方隶属或背书关系。

1. 配置与分析范围

未发布的安全改进：已知 Money、支付、钱包、账户、设置、登录和私信路径不运行帖子或草稿处理。进入这些路径会取消本页任务、移除 SuperX 界面并清除本页临时内容；既有历史和已发出的请求不会因此删除或撤回。直接打开排除页面后，请在支持的 X 页面完整刷新后再使用 SuperX。扩展仍有 X 域名权限；路径检查不能隔离恶意更新或未知的新路径。建议使用没有钱包或支付用途的独立浏览器配置及无资金的研究用 X 账户。手动控件拒绝网页伪造事件；API Key 和 OAuth 请求均不携带 Cookie、拒绝重定向，并禁用 HTTP 缓存及来源网址。

新安装默认选择「订阅登录 · The X Subscription」，通过浏览器内 OAuth 登录，无需 API Key、CLI 或额外程序；另有「Grok API Key」和「本机 Grok Build · CLI / ACP」。已有来源及独立设置不变；旧设置非空但没有来源，或设置缺失／为空但留有旧凭据时，保留 API 路径。由你本人在官方 xAI 页面核对短码并确认权限，不会自动回退到其他凭据或更改账户预算。扩展没有单独的数据同意勾选或 ZDR 声明步骤。暂停自动分析可停止新的自动请求；清除或更换 API Key 会取消相关工作，并清除原会话 Key 与缓存。已经发送的数据无法收回。

分析不限于公开帖子。

受保护帖子、回复，以及喜欢或书签页面中的帖子，只要以支持的帖子元素出现在启用的页面中，也可能被发送给 xAI。即使 xAI 无法凭链接访问某条帖子，页面可见的正文仍可能作为上下文发送。打开不希望上传的内容前，请先暂停 SuperX。

私信和独立 Grok 页面不参与分析或历史记录。SuperX 不读取 X 登录 Cookie，不访问浏览器其他网站的历史，也不向 xAI 发送 X 会话凭据。独立的本机浏览历史会记录 SuperX 和历史记录启用时实际可见的支持帖子，详情见下文。它不会自动发帖、评论、点赞或转发。评论建议始终是草稿；点击复制后，由你自行编辑和发布。

2. 发送给 xAI 的信息

API Key 和 OAuth 模式通过 HTTPS 从扩展后台直接发送至 api.x.ai，三种来源使用相同的帖子上下文。根据所用功能，请求可能包含：

  • 原始帖子的规范链接和帖子 ID。
  • 当前页面显示的正文、语言标记、作者标签和发布时间。
  • 媒体是否存在、符合条件的 X 图片及其可访问描述、可用的引用帖子上下文。已发布主帖、直接回复上级、讨论原帖／祖先及最多两层引用可提供图片输入；每个来源最多四张、每次请求最多 24 张不重复图片，超出上下文预算的图片可能省略。已发布视频的缩略图只是一帧，不是完整视频；提供图片不保证模型正确理解。
  • 所选模型、推理档位、回答语言、搜索设置、生成流程、实际生效的任务指令，以及你选用的自定义提示词。
  • 可选评论草稿请求所需的已有核查结果。事实核查本身只有一次生成请求，不附带先前解释。

所选 API Key 或 OAuth 访问 Token 作为 Bearer 认证凭据仅发送给 xAI，不发给 X 页面。使用搜索功能时，请求会让 xAI 的工具检索原帖和相关证据，工具可能取得其他帖子、网页或媒体。API／OAuth 请求把符合条件的已发布图片 URL 作为原生图片输入，由服务商读取。SuperX 不会独立预加载每条完整帖子或视频。本机 Build 模式会从限定的 pbs.twimg.com 媒体路径读取图片字节，不带凭据、拒绝重定向、不使用 HTTP 缓存，校验 PNG／JPEG 后经本机连接发送 base64 图片块；发送前检查官方运行时的图片能力。能力不支持、图片丢弃或读取失败会报错，不会静默改为仅发送文字。Build 另有每次请求合计 8 MiB 图片字节上限。

OAuth 创建设备码、轮询、刷新和尽力撤销刷新 Token，仅请求固定 auth.x.ai/oauth2/ 端点；打开的授权链接严格限制为官方 accounts.x.ai 或 auth.x.ai 设备页。该网页自己的登录、Cookie 和政策适用；SuperX 不读取账号密码或网页 Cookie。短码／授权链接仅供可信扩展界面显示，设备码与访问／刷新 Token 不传给帖子脚本、不写入公开配置、生成历史或诊断。

当前使用共享的公开 Grok OAuth 客户端，官方页可能显示 Grok Build，不是 SuperX 独立注册的授权身份或官方合作声明。新授权仅请求 openid offline_access grok-cli:access api:access，不请求 profile／email，不获取或使用账号资料信息。这两项可选资料权限见 OpenID Connect §5.4；offline_access 请求刷新授权，见 §11；Grok 访问权限及实际授予范围由服务商决定，见 OAuth 2.0 §3.3。登录只读取模型目录，不发送测试生成或冒用 CLI 身份头。

已有登录不会自动退出，新请求范围缩小不会追溯缩减旧授权；权限范围不同的待完成设备登录会清除，需重新开始。若要取得新的授权范围，请先退出再重新授权。套餐资格、模型、额度和费用仍以账号与提供方规则为准。

2a. 手动草稿核查

在支持的发帖／回复编辑器中，只有明确点击「核查」才会发送点击时的草稿文字和受支持的附图。仅在点击时，SuperX 读取原生上传预览（同源 blob URL 或符合条件的 X 媒体预览），不读取任意本地文件或剪贴板。支持最多四张 PNG／JPEG，图片文件合计不超过 8 MiB（不计 base64 编码膨胀），也支持只有图片的草稿。图片读取失败、格式不支持或超过上限时，本次操作会报错，不会静默改为只发文字。草稿视频附件不会作为图片输入上传，仍未核查。输入、修改内容、打开编辑器或展开已有回答不会自行触发新的草稿核查。暂停信息流自动分析或收起右栏后，仍可主动请求草稿核查；所选账号的额度、费用、搜索和服务商规则仍然适用。

请求可附带新帖中的引用帖，或回复所在讨论的原帖、中间回复及直接父帖，包含规范链接及有界文字快照，也可能包含你可见的非公开正文。X 临时移除已读帖子的页面元素时，已知上下文可保留在当前页面内存中；一次请求最多保留六条较早讨论内容（原帖和最近回复），另加直接父帖。可用的引用帖最多包含两层嵌套引用，每层最多两条。没有可靠原帖链接的原生预览可作为正文、作者和时间快照提供；SuperX 不会编造帖子链接，也不会把这些快照当作已独立验证的来源。上下文有长度上限，可能为适应请求预算而缩短。这些内容用于理解草稿，草稿始终是核查对象。草稿文字和受支持的附图是核查对象，上下文图片仅用于辅助理解。排除的视频或其他附件可带有未核查媒体标记。回答跟随草稿文字的主要语言；没有草稿文字时，参考图片中可读文字的语言，并使用当前模型、推理档位、搜索设置和实际指令。OAuth／API Key 模式直接请求 xAI，本机 Build 模式经官方本机 Grok 服务处理；同样适用本政策的凭据保护与服务商保留限制，没有 SuperX 中转。

草稿快照、已读取的图片字节／base64、回复上下文及生成结果仅保留于当前页面／任务的运行内存，不写入答案缓存、浏览历史或本地排障日志。收起面板、切换浏览器标签页或临时替换编辑器可保留同一个内存任务；页面导航、刷新或关闭标签页会清除该页面保留的草稿与结果。本机清理不能收回已经发送的请求，也不能删除服务商记录。被单独浏览的原帖仍可能由普通浏览历史功能记录，这不包含尚未发布的草稿。

SuperX 在原生操作栏下显示结果，不修改或提交草稿；继续编辑会标记现有结果已过期，更新需再次明确核查。草稿核查不自动发帖、不生成图片，也不复制或附加文件。

3. 第三方处理与数据用途

SuperX 开发者不运营 API 中转、分析或遥测服务。分析和评论请求直接发送给 xAI；xAI 对请求、日志和工具数据的处理受其自身条款、政策与账号配置约束。

API 请求设置 store: false，但这不能保证 xAI 不保留请求、日志或工具输入。xAI API 数据与安全说明介绍默认保留和可选的团队级 ZDR；数据处理附录另行规定个人数据应使用启用 ZDR 的 API。公开帖子也可能含个人数据。扩展不检查或配置这些服务商条件，普通 Key 或 store: false 本身不代表符合其要求；另见 xAI 企业服务条款。

SuperX 对用户数据的使用和传输遵守 Chrome 网上应用店用户数据政策及有限使用要求。帖子内容及相关浏览活动仅用于事实核查、评论草稿和本机近期历史功能及必要缓存，不用于广告定向、数据交易、信用判断或无关画像。

模型返回的 Markdown 在本机解析。扩展不执行模型 HTML，也不加载模型提供的图片。安全的 HTTP(S) 来源链接仅在你点击时打开；访问来源网站、API 控制台或帮助链接是单独的网站交互，适用其各自政策。X 自身仍独立进行正常的页面请求。

4. 本机保存的数据

记住 API Key
默认勾选记住 Key，以 AES-GCM 自动加密保存。密文位于本机扩展存储 apiKeyEncrypted，随机生成的不可导出加密密钥单独保存在扩展 IndexedDB 中。重启浏览器后自动恢复到受限会话存储，无需密码或手动解锁。
会话 Key
未选择“记住 Key”时，Key 仅保存在浏览器会话扩展存储和必要运行内存中，扩展不会刻意跨会话持久保存；重启浏览器后需重新填写。Key 仅供可信扩展界面与后台使用；内容脚本仅获知 Key 是否可用。
OAuth 登录
默认记住登录：刷新 Token 密文保存在独立的 superxOAuthCredential 本机记录，独立随机不可导出的 AES-GCM 密钥位于扩展 IndexedDB。访问 Token 只在受限会话存储和后台内存中，不持久写入本机存储；关闭记住登录后，刷新 Token 也仅在会话中。无需密码、不使用同步。临时设备挑战只在受限会话存储；本机保留授权身份、轮换版本、模型目录和期限等元数据。
本机 Grok 连接
连接码在本机自动加密保存，与 API Key 分开；端口作为本机设置保存。仅可信扩展页面和后台使用，不传入帖子脚本，不使用浏览器同步。
设置
设置、自定义提示词、Key 保存偏好和最近报告的 X 界面语言保存在本机，直到你更改或移除扩展数据。
分析和评论缓存
仅保存在浏览器会话扩展存储中，在当前会话内最多重用 24 小时，最多 160 项、约 4 MB。包含生成文本、评论、来源、模型与用量信息、完成时间以及缓存身份；身份可能包含帖子 URL、设置、提示词、帖子／引用快照和已有分析。浏览器会话结束时清除，不跨新的浏览器会话。
手动核查的草稿
仅在页面／后台运行内存保留未发布文字和图片快照（包括字节／base64）、可用回复上下文及核查结果，不写入上述缓存、浏览历史或排障日志。导航、刷新或关闭标签页会清除该页面保留的草稿和结果。
近期浏览历史
默认记录 SuperX 启用时实际可见的支持帖子，无需停留、API Key 或分析完成。规范帖链接／ID、当前正文（最多 12,000 字符）、作者、语言、媒体存在标记、首次／最近浏览时间与次数保存在未加密、受限的本机扩展存储 superxHistory。已有回答（最多 30,000 字符）、最多 20 个安全出处、模型／Token 信息及三条评论草稿可一并保留。重启后仍可查看，按最后浏览保留 24 小时，最多 1,000 条、约 6 MB；超出容量可能提前删除旧条目。可能包含非公开帖子，不保存图片文件或完整帖存档。
临时状态
每个标签页的计数、折叠状态和会话界面语言保存在会话存储。旧版账户限制和模型繁忙的暂停记录会在启动时清理，单条报错不会暂停其他帖子。本地 API 排障日志在受限会话存储保留最近 24 小时最多 30 条错误，包含脱敏的服务端错误说明、追踪编号、时间／耗时、传输状态与模型设置，不刻意记录请求正文、帖子、提示词或 API Key。可在设置底部查看、复制和单独清除，不自动上传；分享前请检查错误说明中的运行信息。页面快照、部分回答和排队任务保存在相关页面／后台运行期间的内存中。滚动或 X 临时卸载帖子时，已开始的任务继续运行；页面额外保留最多 100 个非活动的离屏回答卡片，导航或关闭页面时清除。

会话缓存可能重复原帖内容，并非匿名索引。设置、自定义提示词和浏览历史不加密，扩展不使用浏览器同步保存设置、Key 或历史。自动加密可保护单独泄露的密文或本机设置存储，不能保护密文与 IndexedDB 同时泄露、整个浏览器配置、包含这些记录的备份或已被控制的运行环境／设备。「不可导出」仅限制 Web Crypto 导出原始加密密钥，不代表绑定操作系统凭据或硬件。请将 Key、提示词、缓存、历史及已显示内容视为可能敏感的数据。

升级时可复用已有明文 Key 或旧版可用的会话 Key；选择记住 Key 时先完成加密保存，再删除明文记录。选择仅会话保存时，删除持久 Key 记录及本机加密密钥。密文或加密密钥缺失、损坏时，请重新填写一次 API Key。新版不解密旧版密码加密记录，旧记录仅保留到成功迁移、更换或清除 Key。旧的数据同意字段不再使用，也不再控制分析。

升级后后台初始化时会删除旧版保存在本机持久存储中的结果缓存，不将其私密内容迁移到新的会话缓存。新结果只在当前浏览器会话中缓存；浏览历史是另一个持久保存功能。

历史仅在本机保存，不作为历史集合上传，也不使用同步。重复帖子合并，按最后浏览排序；再次实际浏览会刷新该帖的 24 小时期限。搜索、展开或查看已有回答不会调用 API、恢复生成或自动请求远程图片；点击原帖或出处才访问相应网站。它不为补齐历史而检索未显示内容。

答案缓存及历史中的生成回答／评论按连接来源和 OAuth 授权身份隔离；切换来源或账号后不显示先前来源／账号的生成内容，本机帖子访问记录仍保留。这不是对旧历史数据或页面已显示结果的取证级擦除。API Key、OAuth 刷新 Token、本机连接码使用独立密钥和记录，清除一种不会销毁另一种；自动加密的保护边界与上文相同。

OAuth 按提供方返回的有效期刷新；先持久记录轮换意图，再交换刷新 Token，并确认新记录保存成功后才使用。网络结果不确定、记录不匹配或保存失败时要求重新登录，不反复使用可能已被消费的旧 Token。后台定时与按需刷新属于认证请求，不发送生成问题；没有帖子分析时也可能请求认证端点。生命周期错误仅保留固定类别，诊断不记录 OAuth 凭据或原始 Token 响应。

5. 到期、删除与控制

  • 暂停／停用：停止自动分析和新的历史记录，不会删除 Key、缓存或已有历史。已经到达 xAI 的请求仍可能完成或计费。
  • 折叠：取消等待中的工作并恢复 X 侧栏；已经开始的请求可能完成。折叠不等于暂停所有请求或清除凭据。
  • 更换 Key：取消旧请求并清除原会话缓存，保留浏览历史，再应用新的 Key；已经到达 xAI 的请求仍可能计费。
  • 清除 Key：取消任务并移除密文、IndexedDB 加密密钥、旧版 Key 记录、会话凭据和会话缓存；不删除浏览历史，不在 xAI 撤销 Key，也不删除已经发送的请求。需要撤销 Key 时，请在 xAI 控制台操作。
  • 清除缓存：移除会话结果缓存，不清除 Key、设置、浏览历史、xAI 记录或已显示在打开页面上的回答。刷新页面可清除已显示结果；之后完成的新请求可能再次写入缓存。
  • 历史控制：关闭「保存浏览历史」停止新增记录及回答更新，已有记录保留至到期。可删除单条或清空全部历史，不清除 Key、答案缓存、服务商记录或 X 中已显示的回答。记录仍开启时，之后实际浏览帖子可以创建新记录。
  • 改为会话保存：取消“记住 Key”并保存后，删除密文、IndexedDB 加密密钥及旧版持久 Key 记录，当前 API Key 仅保留于会话。会话 Key 不会未经选择记住 Key 自动持久保存。
  • OAuth 取消／退出：取消使待授权登录失效；退出清除该连接的本机／会话记录及加密密钥，取消其任务并尽力向官方撤销最新已知刷新 Token。迟到结果不能恢复已取消登录或覆盖新登录。不删除帖子访问记录、API／本机配置、浏览器网站登录或服务商记录；网络不可达时无法保证撤销。
  • 关闭记住登录：移除 OAuth 持久刷新 Token，当前登录只留在受限会话；新的浏览器会话需重新登录。切换来源取消待授权登录，但保留已连接凭据，不自动以其他凭据回退。

清除扩展记录不保证从设备、旧备份或浏览器存储残留中完成取证级擦除。

24 小时是会话缓存的重用到期时间，不是定时删除保证。后台初始化和保存新缓存时会修剪过期、格式错误、未来时间或超出预算的条目。过期条目可能留在仍运行的浏览器会话中，直到下次修剪或主动清除。浏览器会话结束时缓存会清除，不跨新的浏览器会话；仅关闭 X 标签页并不等于结束浏览器会话。通过浏览器卸载扩展或移除扩展数据是更全面的本机删除操作；第三方记录须另行处理。

浏览历史的 24 小时独立期限从最后浏览开始。到期条目不再显示，并在后台启动、历史读写及每小时 alarms 清理中删除。浏览器未运行、调度延迟或存储错误可能延迟实际删除，不保证精确时点擦除。浏览历史跨重启保留，容量上限可能使旧记录提前移除。

SuperX 没有独立的费用预算或帖子数量上限。启用自动分析后，所有可见且符合条件的帖子都可能产生付费请求；请先了解 xAI 计费。

API Key／CLI 的求证和评论遇到临时错误后等待 3 秒，每条最多额外重试 5 次，使用原提供方、模型及推理设置，可能再次发送上下文并消耗额度或费用。Key 无效、账户限制、不支持的设置、输出上限及本机取消未确认不自动重试。OAuth 收到 HTTP 200 后的流错误、未完成或超时不自动重放；首次 HTTP 401 拒绝可刷新授权并恢复请求一次。单条失败不会停止其他帖子。

Grok CLI／ACP 模式：帖子上下文、指令、模型／推理选择和可选已有核查，通过固定本机地址 127.0.0.1 的 WebSocket 直接交给用户启动的官方 Grok 服务，再由官方客户端认证并发送至提供方，不使用扩展 API Key，也不安装额外 SuperX 程序。此本机模式不读取或复制官方客户端的登录文件、OAuth Token 或 X Cookie；生成的启动命令让官方客户端读取自己的默认登录，同时使用临时隔离的 Grok home／工作目录，保留个人配置，关闭导入的 coding／MCP 集成。每个帖子使用新会话，实际检查本地函数数为零并拒绝反向文件、终端和权限请求。工具限制不等同于系统沙箱。提供方账号与 Build 条款、保留策略适用；API 的 store: false 不代表 Build 的保留行为。

本机连接码随机生成，与账号密码和 API Key 不同，作为握手凭据仅发往固定本机地址，不发给 X 或 SuperX 服务器，不进入公开配置、历史或诊断文本。保存时在本机加密，保护范围与已保存 API Key 相同；完整浏览器配置或设备被控制时不能提供保护。复制的命令、剪贴板、终端历史及调试工具可能保留连接码；请勿公开，泄露后停止旧服务并生成新码。官方服务本身不限制只有 SuperX 浏览器来源可以连接，具有连接码和本机访问条件的人可能控制该服务。

浏览器断线不保证官方任务停止；SuperX 会明确请求取消和关闭会话，必要时只为清理重连，不重发问题。若无法确认停止，会提示用户在服务终端按 Ctrl+C。已经提交的工作仍可能消耗额度。正常命令退出尝试清理临时目录，崩溃可能留下文件；官方客户端还可能生成会话标题等辅助请求。移除扩展不会卸载或停止官方 Grok；清除扩展 Key 不退出官方登录，请使用官方 logout。不会自动切换提供方；停止未确认时不会自动重试。

6. 权限

  • storage：保存本机设置、近期浏览历史、独立加密的 API／OAuth／本机凭据，以及受限会话凭据和会话缓存。

SuperX Privacy Policy

Last updated: October 24, 2026 · SuperX 1.0.0

This policy describes how SuperX 1.0.0 handles data through Grok subscription OAuth, your API Key or official local Grok Build, for fact checks, optional reply suggestions and manual checks of unpublished drafts, including image inputs. Draft text and supported attached images are sent only when you explicitly request a draft check. SuperX is independent and is not officially affiliated with or endorsed by X, Grok, or xAI.

1. Setup and analysis scope

Unreleased security hardening: Known Money, payment, wallet, account, settings, authentication and private-message routes do not run feed or draft processing. Entry cancels page tasks, removes SuperX UI and clears transient page content; this does not delete saved history or recall submitted requests. After a direct excluded-page load, fully reload a supported X page to activate SuperX. X host permissions remain: route checks cannot isolate a malicious update or unknown future route. Use a separate research profile and unfunded X account, without wallet or payment use. Manual controls reject synthetic page events; API Key and OAuth requests omit cookies, refuse redirects and disable HTTP caching/referrers.

New installations default to Sign in · The X Subscription, using browser-only OAuth without a Key, CLI or extra program. The other choices are Grok API Key and Grok Build · Local CLI / ACP. Existing selections and independent settings remain intact; nonempty older settings without a source, or missing/empty settings with legacy credentials, keep API. You check the code and approve access yourself on the official xAI page. No route automatically falls back to another credential or changes account budgets. There is no separate SuperX data-consent checkbox or ZDR-attestation step. Pause automatic analysis to stop new requests. Clearing or replacing an API Key cancels related work and clears its previous session credential and cache; data already sent cannot be recalled.

Analysis is not limited to public posts.

Protected posts, replies, and posts visible in likes or bookmarks can be sent to xAI when they appear as supported post elements on an enabled page. Even when xAI cannot retrieve a post by URL, its visible text can still be sent as context. Pause SuperX before viewing content you do not want transmitted.

Direct messages and standalone Grok pages are excluded from analysis and history recording. SuperX does not read X authentication cookies, access the browser's history of other sites, or send X session credentials to xAI. Its separate local history records supported posts actually visible while SuperX and history recording are enabled, as described below. It does not automatically post, reply, like, or repost. Reply suggestions remain drafts; you choose whether to copy, edit, and post them.

2. Information sent to xAI

API Key and OAuth requests go directly over HTTPS from the extension background worker to api.x.ai. All three connections use the same post context. Depending on the feature used, a request can include:

  • The original post's canonical URL and post ID.
  • The currently displayed text, language mark, author label, and timestamp.
  • Media presence, eligible X-hosted images and accessible descriptions, and available quoted-post context. Published targets, reply parents, thread roots/ancestors and up to two nested quotation levels can supply image inputs: up to four per source and 24 unique images per request, with possible omissions under the context budget. A published video thumbnail is one still frame, not the video. Providing an image does not guarantee that the model understood it.
  • The selected model, reasoning effort, answer language, search settings, generation flow, effective task instructions, and any selected custom prompts.
  • The existing Fact Check for an optional reply-drafting request. Fact Check itself uses one generation request and does not include an earlier explanation.

The selected API Key or OAuth access token is sent only to xAI as Bearer authentication, never to the X page. Search-enabled requests ask xAI tools to retrieve the original post and relevant evidence; those tools may retrieve further posts, pages, or media. API/OAuth requests supply eligible published-image URLs as native image inputs for the provider to retrieve. SuperX does not independently preload every complete post or video. In local Build mode, the extension fetches eligible PNG/JPEG bytes from restricted pbs.twimg.com media paths with credentials omitted, redirects refused and no HTTP cache, validates them and sends base64 image blocks over the local connection. The official runtime must advertise image support; unsupported, dropped or unreadable images produce an error rather than a silent text-only retry. Build has an additional combined limit of 8 MiB of image bytes per request.

OAuth device-code creation, polling, refresh and best-effort refresh-token revocation use fixed auth.x.ai/oauth2/ endpoints. Authorization links are restricted to official accounts.x.ai or auth.x.ai device pages. The site's own login, cookies and policies apply; SuperX does not read your password or website cookies. Trusted extension UI alone receives the short code/link. Device codes and access/refresh tokens are excluded from feed scripts, public configuration, generated history and diagnostics.

This route uses the shared public Grok OAuth client, so the official page may display Grok Build, not a separately registered SuperX identity or official partnership. New authorizations request only openid offline_access grok-cli:access api:access, omitting the optional profile/email claim scopes in OpenID Connect §5.4. SuperX does not fetch or use account-profile information. offline_access requests refresh access (§11); Grok access scopes and the actual grant remain provider-controlled (OAuth 2.0 §3.3). Login reads the model directory without test generation or CLI identity headers.

Existing logins are not automatically signed out, and a narrower new request does not retroactively reduce an old grant. A pending device login with a different stored scope is discarded and must be started again. Sign out and authorize again to obtain a new grant. Plan eligibility, models, allowance and charges remain provider- and account-dependent.

2a. Manual draft checks

In supported post/reply composers, only an explicit click on Check sends the text snapshot and supported attached images present at that click. Only then does SuperX fetch native upload previews (same-origin blob URLs or eligible X media previews); it does not inspect arbitrary local files or the clipboard. Up to four PNG/JPEG images with a combined image-file size of 8 MiB before base64 encoding are accepted, including image-only drafts. Failed, unsupported or oversized images stop that attempt with an error rather than a silent text-only request. Draft video attachments are not uploaded as image inputs and remain unchecked. Typing, editing, opening the editor or expanding an existing answer does not itself send another draft-check request. A draft can still be explicitly checked while automatic feed analysis is paused or its rail is collapsed. The selected account's allowance, billing, searches and provider rules still apply.

A request can include a new post's quotations, or a reply's available thread root, earlier replies and direct parent, with canonical URLs and bounded text snapshots that may include non-public text visible to you. Known context can remain in page memory when X temporarily removes posts from its DOM. A request retains up to six earlier thread posts (the root and nearest replies), plus the direct parent. Available quoted posts can include up to two nested quotation levels, with at most two quotations per level. Native previews without a reliable permalink may be included as text, author and time snapshots; SuperX does not invent a post URL or treat those snapshots as independently verified sources. Context is bounded and may be shortened to fit the request budget. These posts support interpretation; the draft remains the target. The draft text and its supported attached images remain the target; contextual images only help interpret it. An unchecked-media flag can indicate excluded video or other attachments. The response follows the draft text's predominant language, or legible image text when no draft text is present and uses the selected model, reasoning, searches and effective instructions. OAuth/API Key requests go directly to xAI; Build requests pass through the official local Grok service. The same credential and provider-retention limitations apply, without a SuperX relay.

Draft snapshots, captured image bytes/base64, reply context and findings remain only in page/worker runtime memory for that page's task, not in the answer cache, browsing history or local diagnostic log. Collapsing the panel, switching browser tabs or temporarily replacing the editor can preserve the same in-memory task; page navigation, reload or tab closure clears the page's retained drafts and results. Local cleanup does not recall submitted requests or delete provider records. An original post independently viewed in the feed can still be recorded by ordinary browsing history; that does not record the unpublished draft.

SuperX displays findings below the native action toolbar without editing or submitting the draft. Continued edits mark the result as stale; updating it requires another explicit check. Draft checks do not automatically post, generate images, copy or attach files.

3. Third parties and purposes

The SuperX developer operates no API relay, analytics service, or telemetry endpoint. Analysis and reply requests go directly to xAI. Its handling of requests, logs, and tool data is governed by its own terms, policies, and account configuration.

API requests set store: false, which does not guarantee that xAI retains no requests, logs, or tool inputs. Its API security documentation describes default retention and optional team-wide ZDR; its Data Processing Addendum separately requires ZDR-enabled processing for Personal Data. Public posts can contain Personal Data. SuperX does not check or configure these provider requirements, and a normal key or store: false does not establish compliance. See also the xAI enterprise terms.

SuperX's use and transfer of user data adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. Post content and related browsing activity are used only for factual-claim analysis, reply-drafting and on-device recent-history features and necessary caches, not for advertising targeting, data sales, credit decisions, or unrelated profiling.

Model Markdown is parsed locally. SuperX does not execute model HTML or load model-provided images. Safe HTTP(S) source links open only when clicked. Visiting a source, API console, or help link is a separate interaction subject to that site's policies. X continues its normal page requests independently.

4. Data stored on your device

Remembered API key
Remember Key is selected by default and encrypts the API key automatically with AES-GCM. Ciphertext is stored in local extension storage as apiKeyEncrypted; a separate, randomly generated, non-extractable CryptoKey is stored in extension IndexedDB. The worker automatically restores the API key into restricted session storage after browser restart, with no password or manual unlock step.
Session key
With Remember Key disabled, the key is kept in browser session extension storage and necessary runtime memory, not deliberately persisted across sessions. Enter it again after browser restart. The key is available only to trusted extension UI/background contexts; content scripts receive only whether a key is available.
OAuth login
Remember login defaults on: refresh-token ciphertext stays in the separate local superxOAuthCredential record, with an independent random, non-extractable AES-GCM CryptoKey in extension IndexedDB. Access tokens remain only in restricted session storage and worker memory; with remembering off, the refresh token is also session-only. No password or sync is used. Pending device challenges stay in restricted session storage; local metadata records authorization identity, rotation revision, safe model IDs, expiry and preference.
Local Grok connection
The connection code is encrypted locally, separately from the API Key; its port is a local setting. Only trusted extension UI and the worker use it, without browser sync or disclosure to the post script.
Settings
Settings, custom prompts, key-storage preferences, and the last reported X interface language remain in local storage until changed or extension data is removed.
Analysis and reply cache
Kept only in browser session extension storage, reusable for up to 24 hours within the current session, and bounded to 160 entries and approximately 4 MB. Entries contain generated text/replies, sources, model and usage metadata, completion times, and cache identities. Identities can include post URLs, settings, prompts, post/quotation snapshots, and earlier analysis. The cache is cleared when the browser session ends and does not carry into a new browser session.
Manually checked drafts
Unpublished text and image snapshots (including bytes/base64), available reply context and findings remain in page/worker runtime memory only, not in the cache above, browsing history or diagnostic log. Page navigation, reload or tab closure clears that page's retained drafts and results.
Recent browsing history
Recording defaults on for supported posts actually visible while SuperX is enabled, without a dwell delay, API key or completed analysis. Canonical post URLs/IDs, displayed text (up to 12,000 characters), author, language, media-presence flag, first/latest viewing times and counts are kept in unencrypted, restricted local extension storage as superxHistory. Existing answers (up to 30,000 characters), up to 20 safe sources, model/Token metadata and three comment drafts can be retained. It survives browser restart, lasts 24 hours after the latest view, and is bounded to 1,000 posts and approximately 6 MB; older records may be removed earlier to meet limits. It can contain non-public posts and does not save image files or a complete post archive.
Temporary state
Per-tab counters, collapse state, and session interface language are stored in session storage. Legacy account-limit and model-capacity pause records are discarded on startup; a failed task does not pause other posts. A local API diagnostic log retains up to 30 failures for 24 hours within the browser session, with redacted provider details, trace IDs, timing, transport status and model settings. It does not deliberately record request bodies, posts, prompts or API Keys. View, copy or clear it at the bottom of Settings; nothing is automatically uploaded. Review operational details before sharing. Page snapshots, partial answers, and queued jobs remain in memory while their page/worker is active. Started tasks continue when scrolling or X temporarily unmounts a post. A page also retains at most 100 inactive detached answer cards, cleared on navigation or page closure.

Cached output can repeat the original post's contents; the session cache is not an anonymous index. Settings, custom prompts and browsing history are not encrypted, and settings, keys and history are not stored through browser sync. Automatic encryption protects exposure of ciphertext or local-settings storage alone. It does not protect access to the ciphertext and IndexedDB together, a full browser profile, backups containing those records, or a compromised runtime/device. Non-extractable prevents raw CryptoKey export through Web Crypto; it does not bind the key to operating-system credentials or hardware. Treat keys, prompts, cached output, history and displayed content as potentially sensitive.

An upgrade can reuse existing plaintext credentials or an available session key from an older version. When Remember Key is selected, the API key is encrypted before its plaintext record is removed. Session-only storage removes persistent key records and the local encryption key. Missing or damaged ciphertext or encryption keys require one-time API key re-entry. Older password-encrypted records are not decrypted and remain only until successful migration, replacement or clearing. Obsolete data-consent fields are ignored and no longer control analysis.

On worker initialization after upgrade, legacy result caches in persistent local storage are deleted. Their private contents are not migrated into the new session cache. New results are cached only for the current browser session; browsing history is a separate persistent feature.

History stays on this device, is not uploaded as a history collection and is not synced. Repeated posts are merged and ordered by the latest view; viewing a post again restarts its 24-hour period. Searching, expanding or viewing saved answers makes no API request, does not resume generation and does not fetch remote images. Original-post or source links visit their websites only when clicked. History does not retrieve unseen content to complete a saved post.

Answer cache reuse and generated history answers/comments are scoped to the connection source and OAuth authorization identity. Changing sources/accounts does not show the earlier context's generated results; recorded post visits remain. This is not forensic erasure of stored history or answers already displayed. API Key, OAuth refresh-token and local-connection encryption use independent keys and records; clearing one does not destroy another. The encryption protection limits above apply.

OAuth expiry follows the provider's token lifetime. Refreshes serialize, persist a rotation intent before exchange, and confirm replacement storage before use. Uncertain network outcomes, mismatched records or failed saving require sign-in again instead of replaying a potentially consumed refresh token. Alarms and on-demand checks can contact authentication endpoints without any post analysis, but send no generation prompt. Lifecycle errors use fixed categories; diagnostics exclude OAuth credentials and raw token-response text.

5. Expiry, deletion, and controls

  • Pause/disable: Stops automatic analysis and new history recording without deleting keys, caches or existing history. Requests that already reached xAI may finish or incur charges.
  • Collapse: Cancels waiting work and restores X's sidebar. Started requests may finish. Collapse does not pause every request or clear credentials.
  • Replace key: Cancels old requests and clears the previous session cache before applying the replacement key. Existing browsing history remains. Work already sent to xAI may still incur charges.
  • Clear key: Cancels tasks and removes ciphertext, the IndexedDB encryption key, obsolete key records, the session credential and session cache. It does not delete browsing history, revoke the key at xAI or delete requests already sent. Revoke a key in the xAI console when needed.
  • Clear cache: Removes the session result cache, not the key, settings, browsing history, xAI records, or answers already displayed on an open page. Refresh the page to clear displayed results. New completed requests may create new cache entries.
  • History controls: Turn off Save browsing history to stop new records and answer updates while retaining existing records until expiry. Delete one post or clear all history without deleting the key, result cache, provider records or answers displayed in X. A later actual view may create a new record while recording remains enabled.
  • Switch to session-only: Uncheck Remember Key and save to remove ciphertext, the IndexedDB encryption key and obsolete persistent key records, keeping the current API key in session storage. Session-only keys are not automatically persisted without choosing Remember Key.
  • OAuth Cancel / Sign out: Cancel invalidates a pending login. Sign-out clears this connection's local/session records and encryption key, cancels its tasks and attempts to revoke the newest known refresh token. Late results cannot revive cancelled login or replace a newer one. It does not erase post visits, saved API/local settings, website logins or provider records; unreachable providers prevent guaranteed revocation.
  • Disable Remember login: Removes the persistent OAuth refresh-token copy, keeping the current login in restricted session storage. A new browser session requires sign-in. Source changes cancel pending device login but preserve connected credentials, without automatic fallback.

Clearing extension records does not guarantee forensic erasure from the device, older backups or browser storage remnants.

The 24-hour period is a session-cache reuse expiry, not a guaranteed deletion timer. Expired, malformed, future-dated, or over-budget entries are pruned when the worker initializes and when new entries are saved. Expired entries may remain within a running browser session until the next pruning or explicit clearing. The cache is cleared when that session ends and does not carry into a new session. Closing an X tab alone does not end the browser session. Uninstalling or removing extension data through the browser provides broader local removal; third-party records are separate.

History's separate 24-hour lifetime runs from the latest view. Expired entries are excluded from history views and removed on startup, history reads/writes and hourly alarms cleanup. Browser shutdown, scheduling delays or storage errors may postpone physical deletion; there is no exact-time erasure guarantee. History survives restart and can be pruned earlier to meet storage limits.

SuperX has no independent spending budget or post-count cap. All visible eligible posts can trigger paid work when automatic analysis is enabled. Review xAI billing before enabling it.

Grok CLI / ACP mode: Post context, prompts, model / effort choices and optional earlier findings pass directly over a loopback WebSocket at fixed 127.0.0.1 to the official Grok service started by the user. The official client authenticates and sends them to its provider. This mode does not use the extension API Key or install another SuperX program. In this local mode, SuperX does not read or copy the official client's login files, OAuth tokens or X cookies. The generated command lets official Grok read its own default login while using an isolated temporary Grok home / working directory, leaving personal configuration unchanged and disabling imported coding/MCP integrations. Each post uses a new session, actual local-function count is checked as zero, and reverse file/terminal/permission requests are refused. These restrictions are not an OS sandbox. Provider account/Build terms and retention rules apply; API store: false does not establish Build retention behavior.

The randomly generated local connection code differs from an account password or API Key. It is sent only to fixed loopback as the handshake credential, not to X or a SuperX server, and is omitted from public configuration, history and diagnostics. Its saved copy is encrypted locally with the same protection limits as remembered API Keys; a compromised device or full browser profile is outside that protection. Copied commands, clipboard, terminal history or debugging tools may retain it. Keep it private; stop the old service and generate a new code if exposed. The official service does not restrict connections to a SuperX browser origin: someone with the code and local access may control it.

Browser disconnection alone does not stop an official task. SuperX requests explicit cancellation and session closure; reconnection is limited to cleanup, never prompt replay. If stopping cannot be confirmed, the user is told to press Ctrl+C in the service terminal. Submitted work can still consume usage. Normal command exit attempts temporary-directory cleanup; crashes may leave remnants. The official client can generate supporting requests such as session titles. Removing SuperX does not uninstall or stop official Grok; Clear saved Key does not log it out. Use official logout separately. There is no automatic provider fallback; unconfirmed cancellation is not retried.

API Key / CLI transient fact-check and comment failures retry after 3 seconds, up to 5 additional attempts with the same provider, model and reasoning. Retried context can consume allowance or charges. Invalid credentials, account restrictions, unsupported settings, output limits and unconfirmed local cancellation do not retry automatically. OAuth does not replay generation after accepted HTTP 200, stream failure, incomplete output or timeout. An initial HTTP 401 rejection can refresh authorization and recover once. A failed task does not stop other posts.

6. Permissions

  • storage: Settings, recent history, independently encrypted API/OAuth/local credentials, restricted session credentials and result caches.
  • Optional http://127.0.0.1/*: requested for official local Grok access; actual connections use fixed ws://127.0.0.1 and the selected port only. API mode does not need it.
  • alarms: Expired-history cleanup, OAuth device polling and token refresh; these authentication calls send no generation prompt.
  • https://x.com/* and https://twitter.com/*: Observe supported post elements, follow theme/language, and display the result column; read a supported composer's text/image snapshot when Check is explicitly clicked.
  • https://api.x.ai/*: Call xAI directly from the background worker.
  • https://auth.x.ai/*: Fixed OAuth device authorization, token exchange/refresh and revocation; newly added site access may require upgrade approval.

The extension does not request the browser's cookies or history permission or access to all websites. Its recent history comes from visible supported X post elements, not the browser's global history database. Content-script site matching is broader than the supported analysis paths; runtime behavior excludes direct messages and standalone Grok/settings flows.
